# SEO — 技術基礎檢查清單

爬蟲讀不到的內容，等於不存在。這條主線只有一個目標：
**讓不執行 JavaScript 就能取得的 HTML 中，已經包含內容、meta 與結構化資料。**

## 1. 內容曝光

- [ ] 核心頁面是否**不需登入就能開啟？** 位於登入牆後的內容不會被索引。
      若無法全部開放，至少把預覽摘要（第一段、關鍵數字）用 SSR 開放，其餘再設門檻。
- [ ] 用 `curl -sL <url>` 取得的 HTML 裡有正文嗎？若是 SPA/CSR，導入 SSR、SSG 或預先渲染
      （prerender）是第一優先 — 沒有這一步，以下全部都沒有意義。
- [ ] 注意：**CSR 退場陷阱**。即使使用 SSR 框架，特定 hook 或 API 的用法也可能讓整個頁面
      悄悄退回瀏覽器端渲染（例如 Next.js 中沒有 Suspense 包裹的 useSearchParams）。
      每次部署後都要用 curl 重新檢查代表性頁面 — 正文字數突然減少就是事故。

## 2. 網站地圖

- [ ] sitemap.xml 存在，且 robots.txt 有引用
- [ ] 詳細頁面（商品、文章、項目）是否**全部**都在裡面 — 只放列表頁是常見的失誤
- [ ] 若看到接近 5 萬個 URL 或 50MB，就要**事先分片**（sitemap index + 分段檔案）。
      一旦超過上限，整份檔案會被悄悄忽略。
- [ ] 建立新的內容類型時，把它加進網站地圖才算上線 — 漏掉的類型會好幾個月不在索引裡
      （實測：3 種篩選頁面缺漏了好幾週）

## 3. Meta

- [ ] 標題以顯示寬度為準（中文全形字約佔英文兩倍寬，50～60 是英文字元標準，中文要大幅縮短，以實際搜尋結果是否被截斷為準）：核心關鍵字放前面，品牌放後面
- [ ] 描述同樣以顯示寬度為準（中文要比 150～160 英文字元標準大幅縮短）：寫出讓人想點擊的句子（不要把免責或警告文字放進描述 — 只會拉低 CTR）
- [ ] 每個頁面都要獨一無二 — 套用範本讓數百個頁面共用同一段描述，會被判定為重複
- [ ] OG 圖片：分享時的門面。依頁面類型動態產生最理想

## 4. 結構化資料（JSON-LD）

- [ ] 依頁面類型使用對應的 schema：Article、Product、FAQPage、BreadcrumbList、Organization
- [ ] **必須與可見文字 100% 一致** — 把畫面上沒有的內容放進 LD，有被判定為垃圾內容的風險
- [ ] `@id` 規約：同一個實體在整個網站使用同一個 @id。每個頁面都重新宣告 Organization，
      實體就會分裂 — 全站宣告一次，其餘用參照
- [ ] 驗證：部署後用 Google Rich Results Test 或 schema.org validator 確認

## 5. URL 與回應衛生

- [ ] canonical：參數變體與重複路徑都指向同一個正本
- [ ] 多語系網站要讓 hreflang 互相參照（只設一邊無效）
- [ ] 不存在的頁面要回 404，而不是 200 — soft 404 會耗掉索引預算
- [ ] 注意：**404 烘焙陷阱**。在 ISR、CDN 快取層，暫時性故障造成的 404 可能被固化好幾個小時。
      資料查詢失敗時不要回 404，改為 throw（重試）— 「不存在」與「取不到」是不同的事
- [ ] 轉址鏈在 1 次跳轉以內

## 6. 效能與資源

- [ ] 圖片用 WebP/AVIF，並明確指定 width/height（CLS）
- [ ] LCP 對象（主視覺圖片、字型）使用 preload
- [ ] 標誌與圖示要做無損最佳化 — 數百 KB 的標誌被載入到所有頁面，是常見的浪費

## 7. 加速索引

- [ ] IndexNow：新頁面、更新頁面在發布當下立即通知（Bing、Yandex 等採用此協定）。
      台灣的 Yahoo 奇摩搜尋結果由 Bing 提供（以 `references/tw-local.md` 第 1 節的並排比對驗證），所以 Bing Webmaster Tools 加 IndexNow，
      同時涵蓋 Bing 與 Yahoo；詳見 `references/tw-local.md` 第 1 節
- [ ] Google 不支援 IndexNow — 以網站地圖 lastmod 的準確度取勝
- [ ] 大量發布時，把通知也內建進發布流程 — 靠手動通知一定會中斷
