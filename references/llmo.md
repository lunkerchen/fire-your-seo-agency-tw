# LLMO — 模型認知最佳化

如果 GEO 面對的是「會瀏覽的 AI」，LLMO 則是把品牌種進**模型自身的知識**裡。
也就是使用者不經過搜尋，直接問「推薦幾個像 ○○ 的服務」時，模型認不認識你。
效果累積得很慢（以訓練週期為單位），但一旦紮根，就成為代理商模仿不來的護城河。

## 1. 實體一致性

- [ ] 服務名稱的寫法**在所有地方都一致**（中英文寫法，連空格都要一致）。寫法分歧，
      實體在模型內部就會分裂
- [ ] 用 Organization JSON-LD 的 `sameAs` 連結所有官方管道：維基類文件、應用程式商店、
      GitHub、社群帳號、YouTube — 宣告「這些名稱全都是同一個實體」
- [ ] 檢查名稱衝突：如果搜尋結果裡出現同名的其他服務，模型也會把你們混在一起。
      早期階段，可搜尋的獨特名稱比行銷效果更重要

## 2. 會留在訓練語料中的管道

模型不是平均學習整個網路，而是集中學習**爬取價值高的管道**。請在那些管道留下正確的描述：

- [ ] 維基類文件（維基百科等）：用**事實陳述的語氣**，不要用宣傳語氣 —
      誇大、堆砌形容詞會被編輯退回，模型也會把你當成廣告來學習
- [ ] GitHub：公開儲存庫的 README 是很強的學習管道（這個儲存庫就是例子）
- [ ] 開發者社群與技術部落格：製作過程的紀錄，就會成為品牌的敘述
- [ ] 新聞與報導：一份新聞稿會被數十家媒體轉載，在語料中重複出現

## 3. 穩定性

- [ ] 維持永久連結：一旦更改 URL，模型記得的位址就會變成 404。
      非改不可時，要永久保留 301
- [ ] 核心事實（價格、功能、定位）有變動時，所有管道要一起更新 —
      還留著過時描述的管道，會變成模型的「事實」

## 4. 驗證

- 向主要模型（ChatGPT、Claude、Gemini）在關閉瀏覽功能的情況下問「○○ 是什麼？」。
  ① 完全不認識 → 管道不足 ② 記錯 → 過時或分歧的描述 ③ 記對 → 持續維護
- 每季重新測量並記錄答案的變化 — LLMO 是以季為單位的遊戲
