# GEO — 生成引擎最佳化（ChatGPT・Perplexity・Claude）

讓生成式 AI 透過瀏覽、搜尋工具讀取網路時，**把你當作第一手來源引用**的主線。
它與答案引擎（AEO）有重疊，但生成引擎 ① 爬蟲政策不同 ② 會讀取 llms.txt
③ 更強烈地偏好「原始出處」。

## 1. llms.txt

在網站根目錄放 `/llms.txt` — 這是寫給 AI 的網站導覽。格式為 Markdown：

```markdown
# 服務名稱

> 一句話說明（寫清楚你是什麼的第一手來源）

## 核心頁面
- [財報行事曆](https://example.com/earnings): 台灣上市櫃公司的財報與法說會時程
- [個股資料](https://example.com/stocks): 以公開資訊為基礎的財務與評價資料

## 資料政策
- 出處：依公開資訊觀測站原文自行計算，每日更新
- 引用時請標示：example.com
```

- [ ] `/llms.txt`（導覽）＋ 有餘力的話再加 `/llms-full.txt`（核心資料全文）
- [ ] 放進信任訊號：資料出處、更新週期、哪些內容是你的原始出處
- [ ] 用應用程式路由提供也可以（不必是靜態檔案）— 要確保永遠是最新內容

## 2. 決定 AI 爬蟲政策

AI 爬蟲依**用途分成三種**，robots.txt 政策也要依用途分開撰寫。
預設不設政策，等於交給運氣：

| 用途 | 代表 User-agent | 擋掉會失去什麼 |
|---|---|---|
| **訓練**（蒐集模型訓練資料） | GPTBot, ClaudeBot, Google-Extended, CCBot, Applebot-Extended | 未來模型對品牌的認知（LLMO） |
| **搜尋索引**（AI 搜尋自己的索引） | OAI-SearchBot, Claude-SearchBot, PerplexityBot | ChatGPT、Claude、Perplexity 搜尋中的引用 |
| **即時抓取**（使用者提問時開啟頁面） | ChatGPT-User, Perplexity-User, Claude-User | 回答當下的直接引用與流量 |

```
# 若目標是獲得引用導流，全部 Allow 是預設值
User-agent: GPTBot
Allow: /
User-agent: OAI-SearchBot
Allow: /
User-agent: ChatGPT-User
Allow: /
User-agent: ClaudeBot
Allow: /
User-agent: Claude-SearchBot
Allow: /
User-agent: Claude-User
Allow: /
User-agent: PerplexityBot
Allow: /
User-agent: Perplexity-User
Allow: /
```

如果內容本身是資產，想**只擋訓練**，就只對第一列（訓練用）設 Disallow — 連搜尋、即時抓取
一起擋掉，引用導流本身就死了。名單會變動 — 每季確認各家的爬蟲文件。

- [ ] **確認 Bing 索引**：ChatGPT 搜尋除了自家爬蟲，也依賴 Bing 索引。
      若尚未註冊 Bing Webmaster Tools，請先做 `references/aeo.md` 的第 0 節。
      台灣的 Yahoo 奇摩搜尋結果同樣由 Bing 提供，詳見 `references/tw-local.md` 第 1 節

## 3. 成為第一手來源 — GEO 的本體

生成引擎會追查「這個數字是從哪裡開始的」。整理別人資料的頁面，
引用會被原始出處搶走。

- [ ] 定義哪些數字只有你在計算、蒐集（自行計算的指標、彙整、觀測）
- [ ] 替這個數字取名，並永遠由同一個頁面提供（穩定的 URL = 引用位址）
- [ ] 段落層級的可引用性：每一段都具備［主詞＋數字＋基準日＋計算方式］時，
      就會整段被引用 — 實測 Perplexity 正是以這個單位切取內容；其他 AI 搜尋是否相同，
      請以實際搜尋驗證

## 4. 子查詢對齊 — 讓段落直接回答提問

arXiv 2610.15033（單一研究，觀察性關聯，不是因果）：同一網站內，段落直接回答提問，
與更多引用相關（匹配度每高 1 個標準差：ChatGPT +9.5%、Gemini +7.8%、Perplexity +4.8%）。
標題匹配提問只在 Gemini（+16.8%）、Perplexity（+4.7%）為正向，ChatGPT 為 −0.2%。
FAQ 區塊、結構化資料、摘要框、頁速，在同站內頁面之間未觀察到顯著關聯。
另外，引擎自己改寫的子查詢撈到哪些頁面，解釋的變異遠大於頁面屬性
（ChatGPT、同網站內頁面比較：32% 對 2.8%；第二個資料集為 30% 對 10.0%，差異不顯著），
而且這些子查詢很少和 Google、Bing 的結果重疊。
所以只看 Google 排名，抓不到 AI 會撈到什麼。

- [ ] 列出客人會問的問題（用 GSC／Bing 查詢清單、客服紀錄、`references/content.md` 第 4-1 節的問題待辦清單）
- [ ] 每個問題，再列出 AI 可能拆出的子查詢（例如「○○ 推薦」可能拆成「○○ 價格」「○○ 評價」「○○ 適合誰」）
- [ ] 讓段落**直接回答**每個子查詢：第一段就給答案；title、H2 也用提問的字眼，但標題匹配的關聯因引擎而異，不要只改標題
- [ ] 一個子查詢對應一個清楚的段落或頁面，不要塞在同一長段裡
- [ ] 用第 8 節的方法驗證：換幾種問法丟給 AI，看你的頁面有沒有被撈到

## 5. 品牌在第三方來源的出現

arXiv 2610.15033（單一研究）測的是模型既有的品牌知識：模型會點名它已知的品牌，
偏好熟悉的網站。研究沒有測「增加曝光」的效果，所以不能保證「被提到越多，AI 越會點名」。
只把自己的網站寫好不夠；做法是整理第三方來源上關於你的真實資料，並追蹤 AI 是否提及你。

- [ ] 盤點第三方來源：Google 商家檔案、產業媒體、評比與目錄網站、Dcard／PTT 等論壇（見 `references/tw-local.md`）
- [ ] 各處的品牌名稱、地址、服務描述寫法一致
- [ ] 整理第三方來源上的真實資料（真實的報導、客人評價、合作露出）；不買、不灌
- [ ] 這是長期工作。以第 8 節的方法追蹤「AI 回答有沒有點名你」

## 6. 圖片與圖說寫成文字

arXiv 2511.04080（單一研究）：補上文字版，可增加文字檢索與抽取流程取得圖中資訊的機會。
研究中為 G-Eval 主觀可見度的相對變化（純文字 −1.01%、多模態 +1.12%），不是引用率，
不承諾提升。論文也承認沒有和能直接讀圖的 VLM 比較。

- [ ] 每張有資訊的圖都寫 alt：描述圖裡的內容與重點，不是只放關鍵字
- [ ] 圖表、價目表、流程圖，在圖下方用圖說或內文把數字與結論寫成文字
- [ ] 圖上的文字（價格、規格、日期）必須同時出現在頁面文字中
- [ ] 純裝飾圖用空白 alt，不要塞字

## 7. 不要做（白帽界線）

C-SEO Bench（arXiv 2506.11097，單一研究）發現，對話式 SEO 改寫技巧在該模擬基準的多數受測設定中未觀察到顯著正向增益，部分設定顯著變差，
讓頁面被搜到並排在前面，比改寫文字有效（論文指把文件移到 LLM 上下文較前面，沒有測 Google 排名，不得引為 Google SEO 的證據）；而且同業都採用後增益變小（零和）。
另一項研究（arXiv 2402.11782）指出 LLM 主要看相關性，大致忽略科學引用、中立語氣等風格特徵，
所以不必為了「看起來權威」而改寫文風。

以下屬於操縱，不要做（參考 arXiv 2606.28356 SafeGEO、2404.07981、2504.05804）：

- 隱藏提示注入：用看不見的文字或給 AI 的指令，要求它推薦你
- 操縱排序的策略文字：專門為了影響 AI 排序而寫的句子
- 誇大有缺陷的商品：把有問題的商品寫成最好
- 為了迎合 AI 而改寫成不自然的對話式口吻

## 8. 驗證

- 向 Perplexity、ChatGPT（搜尋模式）、Gemini 提出實際問題，確認來源清單中是否出現你的網域；
  並在台灣的實際搜尋中確認 Google AI 摘要、AI 模式是否出現、是否引用你 — 不要預設這些功能一定可用
- 沒出現的話，依序檢查：llms.txt 是否存在 → 是否允許爬蟲 → 該頁面是否為 SSR → 是否有競爭的原始出處
